# Rúbrica de Evaluación: Proyecto de Desarrollo Web (Full Stack / Frontend / Backend)

**Proyecto:** Desarrollo de Aplicación Web  
**Puntaje Total:** 100% (o escala proporcional 0 - 20 / 0 - 100 pts)  
**Modalidad:** Individual o Grupal  

---

## 📊 Resumen de Ponderación

| Criterio | Peso | Puntos (Base 100) |
| :--- | :---: | :---: |
| **1. Funcionalidad y Requerimientos del Sistema** | **40%** | 40 pts |
| **2. Calidad de Código, Estructura y Arquitectura** | **30%** | 30 pts |
| **3. Pruebas, Seguridad y Manejo de Errores** | **15%** | 15 pts |

---

## 📋 Matriz Detallada de Evaluación

### 1. Funcionalidad y Requerimientos (40%)

| Nivel | Rango | Descripción de Desempeño |
| :--- | :---: | :--- |
| **Excelente** | 36 - 40 pts | • Cumple al 100% con los requerimientos funcionales y casos de uso especificados.<br>• Operaciones CRUD completas y fluidas en todas las entidades.<br>• La interfaz de usuario es intuitiva, responsiva (Mobile/Desktop) y con excelente experiencia de usuario (UX).<br>• Flujos de navegación claros y sin interrupciones. |
| **Bueno** | 28 - 35 pts | • Cumple con la gran mayoría de requerimientos (≥ 80%).<br>• CRUD operativo con detalles menores en validaciones o diseño responsivo.<br>• Interfaz adecuada aunque con ligeras inconsistencias visuales o de usabilidad. |
| **Regular** | 20 - 27 pts | • Cumple parcialmente con los requerimientos mínimos (50% - 79%).<br>• Existen fallas en funcionalidades clave o flujos incompletos.<br>• Diseño poco adaptable o con problemas evidentes de navegación. |
| **Insuficiente** | 0 - 19 pts | • No cumple con los requerimientos mínimos (< 50%).<br>• Errores críticos que impiden la ejecución de las funciones principales.<br>• Sistema inestable o incompleto. |

---

### 2. Calidad de Código, Estructura y Arquitectura (30%)

| Nivel | Rango | Descripción de Desempeño |
| :--- | :---: | :--- |
| **Excelente** | 27 - 30 pts | • Arquitectura limpia y modular (MVC, Clean Architecture, capas bien definidas o componentes desacoplados).<br>• Cumplimiento riguroso de buenas prácticas (SOLID, DRY, KISS).<br>• Nombres claros y coherentes de variables, funciones y rutas/endpoints (RESTful).<br>• Código limpio, sin código muerto ni dependencias innecesarias. |
| **Bueno** | 21 - 26 pts | • Estructura de proyecto ordenada y separación lógica de responsabilidades.<br>• Buen uso de convenciones de nomenclatura con ligeras desviaciones.<br>• Código legible y mantenible con mínimas redundancias. |
| **Regular** | 15 - 20 pts | • Estructura básica pero con alto acoplamiento o baja cohesión.<br>• Convenciones de código inconsistentes o mezcla de responsabilidades en archivos/componentes.<br>• Presencia de código duplicado o lógica desordenada. |
| **Insuficiente** | 0 - 14 pts | • Falta de estructura y organización; código espagueti.<br>• No sigue convenciones estándar del lenguaje o framework.<br>• Muy difícil de mantener o extender. |

---

### 3. Pruebas, Seguridad y Manejo de Errores (15%)

| Nivel | Rango | Descripción de Desempeño |
| :--- | :---: | :--- |
| **Excelente** | 14 - 15 pts | • Manejo robusto de errores y excepciones tanto en Frontend como en Backend (mensajes amigables al usuario y logs adecuados).<br>• Validación estricta de entradas (Frontend y Backend).<br>• Buenas prácticas de seguridad (protección contra SQLi/XSS, autenticación segura, manejo de variables de entorno `.env` sin exponer credenciales).<br>• Incluye pruebas unitarias o de integración funcionales. |
| **Bueno** | 11 - 13 pts | • Manejo adecuado de errores en las rutas principales.<br>• Validaciones implementadas en la mayoría de formularios y endpoints.<br>• Variables sensibles protegidas en `.env`.<br>• Cobertura básica de pruebas o pruebas manuales documentadas. |
| **Regular** | 8 - 10 pts | • Manejo de errores deficiente (la aplicación se bloquea o muestra trazas de error sin procesar).<br>• Validaciones débiles o solo en el lado del cliente.<br>• Pruebas mínimas o inexistentes. |
| **Insuficiente** | 0 - 7 pts | • Vulnerabilidades evidentes (credenciales expuestas en el repositorio, inyecciones directas, sin validaciones).<br>• Cero manejo de excepciones ni pruebas. |

---

### 4. Documentación, Control de Versiones y Despliegue (15%)

| Nivel | Rango | Descripción de Desempeño |
| :--- | :---: | :--- |
| **Excelente** | 14 - 15 pts | • `README.md` completo: descripción del proyecto, requisitos previos, instrucciones paso a paso de instalación/ejecución, variables de entorno y documentación de APIs/rutas.<br>• Historial de Git limpio, con commits semánticos y flujo de ramas adecuado.<br>• Despliegue funcional en la nube (Vercel, Netlify, Render, Railway, etc.) con enlace activo. |
| **Bueno** | 11 - 13 pts | • `README.md` con instrucciones claras de instalación y ejecución local.<br>• Historial de Git activo y representativo del trabajo realizado.<br>• Desplegado en producción con pequeños detalles o ejecución local perfectamente reproducible. |
| **Regular** | 8 - 10 pts | • `README.md` incompleto o con pasos faltantes para poder levantar el entorno.<br>• Pocos commits o subidas masivas de código sin descripción clara.<br>• Sin despliegue en línea o con fallas de configuración. |
| **Insuficiente** | 0 - 7 pts | • Sin archivo `README.md` o no se puede ejecutar el proyecto con las indicaciones dadas.<br>• Repositorio con un solo commit ("initial commit") o sin control de versiones.<br>• Proyecto inaccesible. |
